# Chat 与 RAG 分阶段改造

| 阶段 | 范围 | 状态 |
| --- | --- | --- |
| 1 | 预置问答与自由输入分流 | 已实现，本地回归通过；未部署 |
| 2 | 统一检索服务，减少检索摘要 Agent | 已实现，本地回归通过；未部署、未进行线上效果对比 |
| 3 | 带产品/版本元数据的共享 manuals 索引 | 已实现，本地回归通过；未上传云端、未切换线上索引 |
| 4 | 灰度切换、停用旧 all 与重复索引 | 待实施 |

## 阶段 1

复用首页配置已有的 `id` 作为预置问题 ID。SDK 点击普通问题时发送 `x-ff-faq-id` 和 `x-ff-faq-scope`（encodeURIComponent 编码）。scope 为 `global` 或 `page:<页面配置 ID>`。标识只绑定对应的 threads.create / threads.add_user_message 请求，不绑定历史读取或其他动作；发送结束或失败后清理。

后端根据当前 URL 重新读取配置，校验页面范围、启用状态、唯一 ID、按钮类型和问题正文。相同 ID 在不同页面通过 scope 区分。无效、停用、问题已变更、没有有效答案时进入普通问答。

答案来源：

1. 当前按钮的 `reply_text`。管理页已提供普通问题的预置答案编辑框，支持页面和全局按钮。
2. 若为空，兼容既有中英文 FAQ Markdown，按完整问题、语言和页面范围精确匹配；多个同等优先级匹配则不快速回答。每次读取当前文件，更新或移除答案无需重启。
3. 无匹配时正常问答，不进行模糊匹配或引用历史模型答案。

自由输入不使用快速回答路径，即使与按钮文字完全相同。Chat 不再读取或新增 `answer_memory.jsonl`，历史文件保留。旧 memory / fuzzy 配置和工具类暂留兼容，但不参与 chat。`FAST_ANSWER_ENABLED=false` 可关闭点击快速回答。

答案正文直接返回后，继续执行原有推荐/购买意图判断；该后处理仍可能调用模型。留资按钮维持现有流程。

部署需要同时更新后端和嵌入 SDK。旧 SDK 不传 ID 时进入普通问答。仅更新后端无法让网页中的旧 SDK 获得新协议。

本地盘点：63 个启用的普通按钮中，60 个可精确匹配现有 FAQ。`manual_navi_1`、`manual_navi_2`、`manual_navi_3` 没有配置答案或对应精确 FAQ，继续正常问答；可在管理页补充经确认的答案。

回归覆盖：中英文、页面/全局隔离、跨域拒绝、停用/删除、重复 ID、即时更新、旧 FAQ 页面标记、自由输入不走快速回答、点击正文不调用模型、保留推荐入口、请求类型与问题匹配。

## 阶段 2

默认流程为 Plan → 并行原文检索 → Output → Post-Decision。保留 Plan 处理语言、型号和上下文，本阶段尚不增加简单问题绕过 Plan 的规则。

- `retrieval_service.py` 封装直接 Vector Store Search API，供 chat 和网站搜索共用。保留产品、价格、新闻独立库；网站搜索仍查原有 all + Aegis Max，索引迁移留到阶段 3。
- 每个产品/领域使用独立查询，并过滤带有错误 product_id 的命中；无元数据的旧产品库仍支持。返回原文、文件 ID、属性和分数，去重并限制证据量，不调用中间摘要模型。
- 页面产品在 Plan 前传入，优先级为本轮明确型号、会话中已确定型号、页面产品。Plan 可输出 clarification_question，直接追问并停止检索和推荐。
- 无结果、未配置库、检索超时与超出服务范围分开处理；保留并发限制、心跳和部分失败降级。推荐判断失败时保留已完成答案。
- 每个原文片段有独立 evidence_id。回答引用 `[[E1_1]]` 等标记，流式隐藏内部标记，完成时转换成原生引用：手册 EntitySource 支持原导航回调，新闻使用 URLSource，缺少页面映射的文件使用 FileSource。未知 ID 不展示引用，未引用的命中不自动列为来源。
- Trace 增加检索模式、Plan/检索耗时、首段正文耗时、总耗时、命中文件/分数和降级状态。它们不是账单成本；准确率、真实延迟和 token 成本仍需联网评测。

配置：`CHAT_RETRIEVAL_MODE=direct` 默认使用新路径；`agent` 可切回中间检索 Agent，重启后生效。该开关仅回退检索实现，不回退第一阶段 FAQ 分流或新的 Plan/Output 提示词。`RETRIEVAL_MAX_RESULTS=6` 控制每域命中数，`RETRIEVAL_MAX_CHARS_PER_PASS=18000` 控制每域原文字符预算；截断片段会明确标记，不得推测未展示的步骤。

旧评测脚本曾引用已移除的 Triage 接口，现在直接调用生产 respond 流程，支持用两个检索模式进行对照。当前只完成离线回归和评测入口检查；没有调用真实 OpenAI 检索或模型，也没有宣称实测提速或准确率提升。

## 阶段 3

新增 `sync_manuals_rag.py`，从 sidebar 引用的 Markdown 生成共享索引。每个章节包含 product_id、source_path、page_slug、language、content_hash、release_id 和 managed_by。产品版本号由完整产品章节及元数据计算；产品内任一章节改变，新版本上传该产品全部章节，避免同一次回答混用章节版本。当前英文内容默认 language=en，可显式指定；不自动翻译文档。

上传完成、完整章节复核及带版本过滤的搜索探测成功后，`--apply --activate` 才原子更新生效清单。`--apply` 单独使用只上传验证。支持 `--all` 初次迁移及 `--product` 独立更新。不会删除任何关联或 Files；旧版本和其他产品保留。重新执行相同内容会复用完成的版本；失败、冲突、重复关联会停止发布。

`MANUALS_INDEX_MODE=legacy` 默认保留旧库读取；`shared` 时 chat 与网站搜索从同一个 `MANUALS_RELEASE_MANIFEST` 获取当前版本。每个请求只读取一次清单，跨产品对比为每个产品建立独立过滤条件；全站搜索使用产品/版本成对的 OR 条件。服务器也过滤不符合元数据的直接检索命中。网站搜索通过 page_slug 映射，避免共享索引文件名碰撞。Agent 检索回退路径也传入产品/版本过滤条件；其来源展示仍沿用旧 Agent 引用提取逻辑。

清单必须匹配共享库 ID 且覆盖 sidebar 全部产品；缺失或非法时，产品检索标记 unavailable，网站搜索返回 error，不回退到旧 all。价格、新闻检索保持独立。清单原子切换只保证单个请求看到一致版本，多实例需发布同一份清单；不是跨实例分布式事务。

回滚保留两层：原子恢复 `.previous.json` 可回退最近一次产品版本；切回 `MANUALS_INDEX_MODE=legacy` 并重启可恢复旧产品库与网站 all 查询。具体操作见 [共享索引同步说明](../apps/rag-api/RAG_SYNC.md#共享-manuals-索引阶段-3)。本地 9 个产品、129 章节校验通过，后端 52 项回归通过；尚未执行真实上传、搜索探测或线上问答评测。

## 后续阶段

阶段 4：分别灰度新流程与新索引，回归全部产品、跨产品对比、模糊追问、无结果与失败降级。确认覆盖与回滚路径后停用旧配置；远程库清理最后执行，先检查共享引用。

阶段 1 没有修改普通问答的 Plan → Loop → Output → Post-Decision 流程，也没有迁移或删除远程向量库。
